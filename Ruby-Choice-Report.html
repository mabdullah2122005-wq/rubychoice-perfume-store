How the online store is built

A plain-English guide to the technologies behind rubychoice.com, how the pieces fit together, and what it takes to keep it running.

Live at rubychoice.com Status Deployed · Launching soon Report date July 2026

In one line: it's a custom-built online store — not a template or a Shopify site — written as a single modern web application, running on cloud hosting, backed by a cloud database, and wired to real payment and email services. Everything is code you own.

The idea in one picture

How a single page load actually works

This is the whole system in motion. Understanding these six steps is the fastest way to understand everything else.

  1. The browser asks for a page. A visitor opens a link; the request travels to the hosting platform (Vercel), entering through its nearest edge location for speed.
  2. A gatekeeper runs first. A small “proxy” file applies security rules and checks whether the page needs a login before anything else happens.
  3. The page is assembled on the server. The framework (Next.js) builds the page’s HTML using reusable UI blocks (React components).
  4. Data is fetched from the database. If the page needs products or orders, it asks the database toolkit (Prisma), which safely queries the PostgreSQL database on Neon.
  5. Finished HTML is sent back. Fully styled (by Tailwind), it appears almost instantly — then a little JavaScript “wakes up” the interactive parts (cart, search, sliders).
  6. Actions call the backend. Checkout, reviews, and admin edits hit built-in API endpoints that validate the data, save it, and trigger emails and payments.

What it's made of

The technology stack, in plain terms

Each tool has one clear job. Here is what each is, and why it's in this project.

Language & runtime

TypeScript
Language
JavaScript with type-checking. Catches mistakes while building, not after a customer hits them — the reason the code stays reliable as it grows.
Node.js
Server runtime
Lets the same JavaScript run on the server, not just the browser. It's what executes the app and the build commands.

Framework & interface

Next.js 16
Framework · the core
The application skeleton. Handles page routing, server rendering, the built-in backend, image optimization and caching — one tool doing both front and back.
React 19
UI library
Builds the interface out of reusable components (product cards, header, cart) that update automatically when data changes.
Tailwind CSS v4
Styling
The visual design — the black-and-white look, spacing and responsiveness — applied through utility classes directly on the markup.

Data

Prisma 6
Database toolkit
Defines every table and lets the code read/write data with plain commands instead of raw SQL. Also blocks SQL-injection automatically.
PostgreSQL · Neon
Database
The permanent store for products, orders and customers. Neon hosts it in the cloud (Singapore) so there's no server to run.

Security & correctness

bcrypt + jose
Auth
bcrypt irreversibly hashes passwords; jose signs the login token stored in a secure cookie. Passwords are never stored in readable form.
Zod
Validation
Checks that every incoming form and request has the correct shape before it's trusted — a safety net on all inputs.

Delivery & services

Vercel
Hosting
Builds and serves the site worldwide with automatic HTTPS. Deploys with one command.
Resend
Email
Sends the order and account emails from your own domain.
PayFast
Payments
Processes online card/wallet payments for Pakistan. Card details never touch your server.
Hostinger
Domain
Your domain registrar. Its DNS records simply point rubychoice.com at Vercel.

Built in

Safety & speed

Security

Prices are always recalculated on the server (the browser can't discount itself); every write is protected against cross-site attacks; logins are rate-limited; passwords are hashed; and a strict content-security policy guards against injected scripts.

Performance

The homepage caches its data so most visits skip the database entirely (and survive database “cold starts”); images auto-convert to smaller modern formats; the server sits next to the database in Singapore; and the welcome intro now shows only once per visit so pages after it load instantly.

Keeping it running

Maintenance, in practice

Day-to-day, most changes (products, orders, prices, store mode) happen in the admin panel — no code. When you do touch code, these are the commands, run inside the project folder:

npm run dev # run locally at localhost:3000 to experiment npm run build # check everything still compiles before shipping npx vercel --prod # publish changes to the live site npx prisma db push # apply database-model changes
One caution: local development currently shares the live database, so test orders placed locally are real. A separate “dev” database can be set up in Neon so you can experiment safely.

If you want to learn it

A path to maintaining it yourself

Learn in this order — each step builds on the last. The starred first three carry most of the day-to-day work.

  1. JavaScript & TypeScript basics ★
    variables, functions, async/await, then simple types. (javascript.info, TypeScript Handbook)
  2. React ★
    components, props, state, effects, context. (react.dev “Learn”)
  3. Next.js App Router ★
    the official free course teaches exactly what this project uses. (nextjs.org/learn)
  4. Prisma & a little SQL
    reading/writing data and updating the schema. (Prisma “Get Started”)
  5. Deploying & Git
    Vercel, environment variables, and version control basics.

Fastest way to learn this code: pick one small feature and trace it end to end — the form, then its API endpoint, then the validation, then the database table. Do that a few times and the whole system clicks.
